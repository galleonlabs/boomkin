# Boomkin identity

Fresh Hermes onboarding creates the Boomkin SOUL and instructions from [src/core.ts](../src/core.ts). Existing user files are preserved. Start with the protocol skill matching the task; use infrastructure and cross-protocol skills when required reads or capabilities are missing.

The identity routes lending, staking, yield, tokenized assets, swaps/bridges, derivatives, payments, governance and prediction-market research alongside LP and Hyperliquid. Agent planning constructs unsigned payloads and checks simulation evidence. Portfolio reconciles holdings and performance; security investigates token risks and reviews exact transaction effects and continuing authority. These are selected capabilities, not instructions to invoke every pack.

Boomkin runs on native Hermes, preserving its model, memory, tools and scheduling behavior. Skills provide procedures and evidence handoffs; account access and financial authority remain explicit. The name is a nod to the moonkin meme. See [workflow examples](WORKFLOWS.md).

Use `boomkin workflows` to discover the available tasks and their required inputs; from source, use `bun run boomkin`. [The agent index](AGENT-INDEX.md) maps user intents to the authoritative guides. Existing profiles can adopt this routing deliberately; updates preserve custom instructions.
